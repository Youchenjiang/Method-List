# STAF框架論文核心解讀總結
這篇論文聚焦**汽車領域網路安全測試自動化**，提出了基於大語言模型（LLM）和自校正檢索增強生成（RAG）的**STAF（Security Test Automation Framework，安全測試自動化框架）**，解決了從攻擊樹手動生成可執行安全測試用例耗時、易出錯，且通用LLM領域生成測試的用例

## 一、研究背景與核心問題
1. **汽車安全測試的必要性**：現代汽車作為網聯化的信息物理系統，ECU、CAN/Ethernet等通信協議擴大了攻擊面，ISO/SAE 21434等標準要求開展結構化威脅建模，**攻擊樹**成為系統梳理攻擊向量的常用工具，但從攻擊樹轉化為可執行測試用例仍以人工為主**遺漏**
2. **現有技術的不足**
 - 攻擊樹相關研究多聚焦靜態分析/威脅文檔，未實現到測試案例的自動化轉換；
 - 通用LLM雖可用於測試用例生成，但在**領域針對性、完整性、可運行性**上存在明顯缺陷，尤其在汽車安全這種高要求場景中表現不佳；
 - 現有工作未實現**威脅識別（攻擊樹）-安全性測試（用例產生）** 的端對端整合。
3. **LLM的應用潛力與挑戰**：LLM具備程式碼產生與結構化資料解析能力，但產生可靠的安全測試腳本仍面臨上下文失準、領域知識不足等問題，需結合客製化框架最佳化。

## 二、論文核心貢獻
1. 提出一種**從攻擊樹自動產生安全測試案例的方法**，實現威脅建模到測試執行的連結貫通；
2. 設計了適配汽車系統的**可執行測試案例產生方案**，解決通用LLM的領域適配問題；
3. 將STAF與現有汽車系統分析工具（AVL ThreatGuard/TestGuard）集成，完成實際場景的落地驗證；
4. 推導了用於**模型檢測的線性時序邏輯（LTL）屬性**，豐富了安全測試的驗證維度。

## 三、STAF框架核心設計
STAF基於**自校正四階段RAG架構**構建，核心目標是將TARA（威脅分析與風險評估）生成的攻擊樹轉化為**可執行Python測試腳本**和LTL模型檢測屬性，整體包含RAG經典組件（源模組、檢索器、生成器、評估器），並增加了領域知識庫和迭代機制，四階段流程如下：

### 1. 攻擊樹分析（Analyze Threats）
- 解析**JSON格式**的攻擊樹，透過LLM結構化提示擷取威脅核心屬性：受影響元件、攻擊前置條件、存取權限要求、漏洞複雜度、攻擊向量間的依賴關係；
- 以汽車UDS協定威脅為例，可精準擷取UDS服務、會話、種子金鑰等細節，為後續檢索及產生提供關鍵字。

### 2. 自校正資訊檢索（Self-corrective Information Retrieval）
- **語義檢索**：基於提取的關鍵字，在**領域專屬向量知識庫**中進行語義搜索，知識庫包含汽車威脅矩陣（AUTO-ISAC ATM）、AVL內部測試庫、ECU UDS協議的Mealy行為模型；
- **相關性評估**：由LLM對檢索文件從**上下文匹配、技術深度、場景適用性**三個維度評分；
- **自校正補充**：若相關文件數低於閾值，透過Tavily API進行網頁搜索，補充廠商公告、汽車安全公告等即時訊息，最終整合為統一知識庫。

### 3. 測試案例產生（Generate Test Cases）
- 結合攻擊樹分析結果和檢索的領域知識，透過客製化提示引導LLM產生**JSON格式的結構化測試案例**；
- 測試案例包含核心要素：描述性標題、測試情境概述、環境建置步驟、可執行Python腳本、系統復原（tear-down）流程、預期測試結果（如漏洞觸發的判定標準）。

### 4. 迭代優化（Chain of Improvement）
- 採用**LLM-as-a-judge**策略，從**對齊性、可運行性、完整性**三個核心指標（0-10分）對測試用例評分，**整體分為三者算術均值**；
- 若未達到品質閾值，LLM輸出具體改善建議（如補充認證機制檢查、完善環境配置），架構依建議重新產生測試案例，循環至達標（最多4輪迭代，評分超90分則停止）。

## 四、實驗評估
### 1. 評估對象與比較向度
- 選取兩款主流LLM：**GPT-4.1**、**DeepSeek-V3-0324**；
- 比較三組實驗版本：原生LLM（vanilla）、STAF整合版、STAF+Mealy協定模型版（STAF&MM）；
- 核心評估指標：<u>對齊</u>（測試案例與攻擊樹威脅的匹配度）、<u>可運行性</u>（程式碼無需修改的可執行程度）、<u>完整性</u>（測試案例的資源、步驟、文件完善度），同時統計產生測試案例的總數和唯一數。

### 2. 核心實驗結果
| 核心結論            | 具體表現                                                                        |
| --------------- | --------------------------------------------------------------------------- |
| STAF大幅提升LLM性能   | GPT-4.1整體分從7.17升至9.11（STAF），DeepSeek整體分從5.11升至6.11（STAF&MM），二者的對齊性、完整性均顯著提升 |
| GPT-4.1適配性更優    | GPT-4.1（STAF）對齊性達9.80，可運行性始終保持9.00以上；STAF&MM版可運行性進一步升至9.67，能產生無佔位符的可執行代碼    |
| DeepSeek需優化可運行性 | DeepSeek的對齊性（9.33）和完整性（9.00）提升顯著，但可運行性為0（代碼含自然語言佔位符，需手動修改）                  |
| Mealy模型增強協定針對性  | 引入協議Mealy模型後，LLM能產生貼合汽車協議的測試用例（如UDS會話切換、未文檔化子功能調用），而原生LLM僅能產生簡單的畸形訊息測試      |

### 3. 定性結果
STAF產生的測試案例能實現**協定級針對性攻擊測試**（如UDS多幀分片畸形攻擊），而原生LLM僅能完成基礎的畸形訊息發送，且STAF能有效過濾物理旁路等不可數位化測試的場景，提升測試集的實用性。

## 五、實際個案研究
以**汽車電池管理系統（BMS）** 為測試對象，驗證STAF的端對端執行效果：
1. **測試場景**：針對BMS的UDS協定**中間人攻擊**攻擊樹，包含三個核心攻擊向量：攔截UDS通訊、注入惡意UDS訊息、繞過實體/邏輯保護；
2. **STAF執行流程**：提交JSON格式攻擊樹→提取關鍵字檢索領域知識庫→因含UDS協議加入Mealy模型→產生測試用例→LLM評估評分→迭代優化（最多4輪）；
3. **輸出結果**：產生包含唯一ID、威脅匹配描述、可執行Python程式碼的測試案例集，同時推導出LTL模型偵測屬性（如`□(DIAG_SESSION_INIT ∧ UNAUTH ￫ false)`，即未認證的診斷會話初始化需被禁止）；
4. **驗證效果**：STAF能精準配對攻擊樹的所有威脅，產生的測試案例可驗證BMS在UDS通訊中的認證缺失、訊息竄改漏洞，且經少量迭代後評分即可超90分。

## 六、研究結論
1. STAF透過**LLM引導的攻擊樹分析、自適應領域知識檢索、迭代式測試用例優化**，實現了汽車領域從攻擊樹到可執行安全測試用例的自動化生成，大幅減少人工工作量；
2. 客製化RAG架構有效解決了通用LLM在領域特定測試產生中的**上下文失準、知識不足**問題，結合Mealy協定模型後，測試用例的協定針對性和對齊性進一步提升；
3. 攻擊樹為測試套件提供了**結構化的威脅覆蓋基礎**，而RAG的上下文知識讓測試案例從「語法正確」升級為「語意有效、可執行、貼合實際攻擊場景」；
4. STAF不僅能產生Python測試腳本，還能推導LTL屬性，實現了**動態測試（腳本執行）+靜態模型偵測**的雙重安全驗證。

## 七、限制與未來工作
### 1. 現有局限性
- 攻擊樹缺乏**具體實作細節**（如CAN波特率、仲裁ID），導致產生的測試案例需手動修改，未實現完全自治；
- 迭代優化過程**資源密集**，複雜汽車系統場景下的處理速度較慢，可擴展性不足；
- 框架仍需**人工監督**，無法完全脫離人工處理邊緣場景和異常情況。

### 2. 未來研究方向
1. 支援產生**領域特定語言（DSL）** 的測試案例，實現後處理注入硬體/協定實作細節，提升自治性；
2. 將STAF與自動化測試框架集成，加入**回饋環**，利用測試工具的錯誤訊息優化LLM的評估與生成邏輯；
3. 對LLM進行**領域微調**，分離測試集和腳本程式碼，縮小上下文窗口，提升回饋準確性和生成效率；
4. 優化檢索和迭代機制，提升框架對**大規模、複雜汽車系統**的處理效率，減少人工幹預。
