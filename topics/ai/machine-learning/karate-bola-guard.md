# LLM-Driven, Self-Improving Framework for Security Test Automation: Leveraging Karate DSL for Augmented API Resilience 論文總結

**發表期刊**：IEEE Access 2025年第13卷

**研究團隊**：羅馬尼亞克盧日-納波卡理工大學等機構的Emil Marian Pasca等學者

**核心貢獻**：提出**Karate-BOLA-Guard**框架，融合大語言模型（LLM）與檢索增強生成（RAG）技術，實現針對API中**Broken Object Level Authorization (BOLA)** 漏洞的自動化安全測試用例生成與自改進，填補了傳統API安全測試的技術空白。

## 一、研究背景與動機

1. **API安全核心問題**：API是現代軟體架構的核心，但BOLA漏洞被OWASP列為最嚴重的API安全風險，其因授權校驗缺失導致未授權資源訪問/篡改，且現代API架構複雜，傳統防護機制難以落地。

2. **傳統測試方法的局限性**

    - 以功能測試為主，缺乏安全專用測試用例生成能力；

    - 無系統檢測BOLA等複雜漏洞的方法，多為“暴力測試”，無法理解參數間依賴，無效請求多；

    - 漏洞發現具有偶然性，而非定向檢測。

3. **現有ML/AI在API安全中的應用不足**

    - 異常檢測僅用SVM線性核，無法捕捉非線性攻擊模式；

    - 流量分類僅聚焦資料洩露/DoS攻擊，忽略API濫用、業務邏輯缺陷等；

    - 模式識別僅適用於C/C++程式，跨語言適用性差。

4. **研究問題**

    - RQ1：RAG技術對Karate DSL測試用例的品質和相關性提升程度；

    - RQ2：RAG增強方法對BOLA漏洞相關API端點測試覆蓋和特異性的影響；

    - RQ3：RAG技術在API安全測試中，測試生成時間、精度、全面性的權衡關係。

## 二、核心理論與框架設計

### （一）定制化評估指標體系

針對BOLA漏洞檢測的非功能測試需求，設計**3個核心可靜態分析的指標**（分值1-5，越高性能越好），均通過`1+Σ（4個維度得分，0-1）`計算，適配Karate DSL格式：

1. **Accuracy (A)**：聚焦BOLA檢測能力，含BOLA模式覆蓋、授權邊界測試、邊緣用例處理、回應驗證完整性；

2. **Complexity (C)**：聚焦測試場景設計，含場景結構、授權邏輯、資料操作、斷言覆蓋；

3. **Interoperability (I)**：聚焦Karate DSL相容性，含語法正確性、認證集成、框架相容性、資料處理。

### （二）Karate-BOLA-Guard框架核心設計

1. **框架定位**：模組化、自改進的自動化框架，專為BOLA漏洞設計，生成Karate DSL格式測試用例，核心融合**LLM+RAG+反覆運算精修**。

2. **核心架構組件**

    - 數據層：OAS解析器（拆解API規範）、ChromaDB向量資料庫（存儲API片段、BOLA案例、Karate DSL示例）；

    - 生成層：LLM服務、RAG系統（增強上下文感知）；

    - 驗證層：語法/相容性驗證器；

    - 執行層：容器化Karate測試運行器；

    - 優化層：測試結果分析器、Langfuse可觀測工具、反覆運算精修模組。

3. **RAG增強測試生成流程**：片段檢索→提示詞增強→測試場景生成→Karate DSL翻譯→相容性驗證→測試執行→結果分析與系統反覆運算。

4. **自改進演算法**：對生成的測試用例進行最多n次錯誤檢查反覆運算，將執行錯誤回饋至向量資料庫，持續優化後續測試生成，確保用例有效性。

## 三、實驗設計

### （一）實驗環境

1. **硬體**：Intel i7-4790K CPU、NVIDIA GTX1070 GPU（8G顯存）、24G RAM；

2. **軟體**：Ubuntu24.04 LTS、Python3.12、Karate DSL1.4.1、Docker；向量資料庫ChromaDB，可觀測工具Langfuse；

3. **LLM配置**：選擇4個開源模型（GGUF Q4_0量化），統一上下文視窗1000token、溫度0.3，保證實驗一致性：

    - Llama 3 8B Instruct、Mistral Instruct 7B、Wizard v1.2 13B、Phi-3 Mini Instruct。

### （二）測試目標API

1. **基礎測試**：3個**故意脆弱的API**（VAmPI：Flask單體架構；CrAPI：微服務架構；OWASP Juice Shop：Node.js現代架構），均含豐富BOLA漏洞實現；

2. **擴展驗證**：15個**生產級API**，覆蓋社交（Instagram）、版本控制（GitHub/GitLab）、金融（Stripe/雅虎財經）、交通（Uber/倫敦交通）等多領域，驗證框架通用性。

### （三）實驗流程

1. 基於API片段生成初始Karate測試用例；

2. 依次進行Karate相容性、語法確認；

3. 容器化執行測試，生成報告並上傳至向量資料庫；

4. 若存在錯誤，進行最多3次反覆運算精修；

5. 全程通過Langfuse監控權杖使用、生成時間、異常資訊等指標。

## 四、關鍵實驗結果

### （一）模型性能對比（GPU環境）

Llama 3 8B為**最優模型**，其餘小模型兼顧速度但精度稍低，核心資料如下：

| 模型          | 平均處理時間(s) | 平均權杖使用/會話 | 精度(A)範圍 | 互通性(I)範圍 | 核心特點               |

|---------------|-----------------|------------------|-------------|-----------------|------------------------|

| Llama 3 8B    | 143.76          | 36,591           | 3.1-4.3     | 3.7-4.4         | 性能最穩定，複雜API適配性優 |

| Mistral 7B    | 72.14           | 25,225           | 2.7-3.4     | 3.2-3.9         | 權杖利用率最高         |

| Phi-3 Mini    | 69.58           | 31,007           | 3.0-3.3     | 3.2-3.8         | 速度最快，精度可接受   |

| Wizard v1.2 13B | -（僅CPU）| 24,486-41,619    | 2.7-3.2     | 2.7-3.7         | 顯存要求高，性能一般   |

### （二）硬體加速效果

**GPU比CPU處理速度提升20-25倍**：Phi-3 Mini CPU平均處理時間1333.78s，GPU僅69.58s；Llama 3 8B CPU超4000s，GPU僅143.76s；Wizard v1.2因顯存限制無法在GPU運行。

### （三）API適配性表現

框架對**複雜API的測試效果顯著優於簡單API**，核心API得分如下（Llama 3 8B）：

- 最優：Instagram（A=4.3，I=4.4）、OWASP Juice Shop（A=4.2，I=4.3）；

- 中等：VAmPI（A=3.6，I=4.3）、Stripe（A=4.1，I=4.2）；

- 最差：CrAPI（A=2.6，I=2.5）、雅虎財經（A=3.0，I=2.6）。

### （四）反覆運算精修與RAG增強效果

1. **反覆運算精修**：主要提升**互通性（I）**（修復語法錯誤、優化框架相容性），精度（A）和複雜度（C）小幅提升；僅Mistral在JuiceShop測試中出現指標小幅下降；

2. **RAG增強**：顯著提升測試用例的上下文感知能力和相關性，減少人工干預；**BOLA定向測試生成準確率100%**（可精准生成BOLA相關用例，非漏洞檢測能力未驗證）。

### （五）測試用例品質分析

- 安全核心邏輯：83.3%的用例實現了良好的認證/授權覆蓋，BOLA漏洞檢測的核心邏輯無明顯缺陷；

- 技術實現問題：44.4%存在Karate DSL語法問題，16.7%存在測試結構問題（如場景大綱格式、回應驗證不規範）。

## 五、研究局限性

1. **資源依賴**：大模型性能優但顯存/計算資源要求高，小模型速度快但穩定性差，資源受限環境部署難度大；

2. **漏洞覆蓋單一**：僅聚焦BOLA漏洞，未覆蓋OWASP API安全Top10的其他漏洞（如注入、破環認證等）；

3. **潛在假陽性**：生成的測試用例可能錯誤識別非-existent漏洞，需進一步優化檢測邏輯；

4. **API選擇偏倚**：生產級API測試基於APIRank的OpenAPI規範，可能存在規範過時、覆蓋不全問題；

5. **評估指標局限**：未包含代碼可維護性、認知複雜度、跨平臺相容性等通用軟體品質指標。

## 六、結論與未來研究

### （一）核心結論

1. Karate-BOLA-Guard框架實現了**LLM+RAG驅動的BOLA漏洞自動化測試**，模組化、自改進特性有效提升了測試的效率、精度和適配性；

2. 回答了3個研究問題：RAG技術顯著提升測試用例品質/相關性、增強BOLA測試的覆蓋和特異性、測試生成存在**時間-精度-資源**的明確權衡（大模型精度高但耗時久，小模型反之）；

3. GPU加速是框架落地的關鍵，可實現20-25倍的性能提升，Llama 3 8B是兼顧精度和實用性的最優模型；

4. 框架對複雜API（如社交、金融）的測試效果更優，且BOLA定向測試生成準確率100%，大幅減少人工干預。

### （二）未來研究方向

1. 開發**動態模型選擇機制**，基於API複雜度即時匹配最優LLM；

2. 優化資源利用率，適配低資源環境的大模型部署；

3. 探索**跨模型學習**，融合不同LLM的優勢構建混合測試框架；

4. 升級RAG技術，引入上下文感知嵌入、自我調整相似度指標；

5. 擴展漏洞覆蓋範圍，將框架適配至其他API安全性漏洞；

6. 構建**BOLA漏洞基準套件**，驗證評估指標的有效性；

7. 加入性能預測模型，實現API測試的資源配置智慧化。
