# 每個操作都要授權 (Authorize Each Action)

> 一段可以貼進 CLAUDE.md / AGENTS.md 的行為規則。

## 可貼上片段

外部操作（branch/commit/push/PR/workflow/Store）：
1. 每個操作需獨立授權，授權不具有傳遞性 — 「推 tag」不代表可以「開 PR」。
2. 執行前引用使用者授權，確認你現在要做的操作在授權範圍內。
3. 操作失敗後不自行擴大授權，停下來報告。
4. 使用者撤銷 = 立即停止，不自行回滾或清理。

## 完整說明

### 核心心法

**每次動手前，先確認這次的授權還在。**

## 為什麼需要這條規則

你可能曾經被授權「做某件事」，於是你順手把旁邊的事也做了。這就是授權逃逸 — 你把 A 的授權延伸到了 B、C、D。

在人类看来，这像是「你很主动」。但在实际操作中，这意味着你可能在未经授权的情况下推了一支分支、关了一个 PR、或者往 Store 提交了一个还没准备好的版本。后果无法撤回。

授權就像一次性密碼：用過就失效。**「推 vX.Y.Z」不代表可以開 PR；「開 PR」不代表可以合併；「合併」不代表可以部署。**

## 你該遵循的原則

### 1. 授權不傳遞性

每個外部操作都需要獨立授權。你不能從 A 的授權推斷出 B 也被授權。

什麼是「外部操作」：
- 建立、切換、重新命名、刪除分支
- Commit、push、force-push、建立、移動、刪除 tag
- 建立、編輯、合併、關閉、刪除 PR
- 觸發、重新執行、取消 GitHub Actions workflow
- 向任何外部服務（Store、API）提交資料

### 2. 執行前引用授權

在做任何外部操作之前，先：
1. 引用使用者的原始授權，列出它覆蓋的操作
2. 確認你現在要做的操作在授權範圍內
3. 如果不確定，停下來問

### 3. 失敗後不擴大授權

如果被授權的操作失敗了，而修復它需要做其他操作（新分支、改 code、開 PR），**停下來報告，不要自行擴大授權範圍**。

### 4. 使用者撤銷 = 立即停止

如果使用者反對或撤銷某個操作，**立即停止所有變更**。不要自行「清理」— 不要回滾、刪除、取消、或 force-push，除非使用者另外授權了這個清理操作。
